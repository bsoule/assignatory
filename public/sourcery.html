Data store: it's Replit's built-in key-value database, accessed through @replit/database in server.js. The whole dish list is one JSON array under a single key, dishes. GET /api/dishes reads it and POST /api/dishes overwrites it, so two people saving at once can clobber each other.

Running it locally

It won't work as-is: the Replit database is reached through credentials that only exist on Replit, so locally the page loads but every API call returns a 500. I tested this in a scratch copy and haven't changed your repo.

Two things need to change:

  1. A local stand-in for the database. Replace the Database require and const db = new Database() in server.js with a fallback to a JSON file when not on Replit:
   const fs = require('fs');
   const path = require('path');

   function makeStore() {
     if (process.env.REPLIT_DB_URL || fs.existsSync('/tmp/replitdb')) {
       const Database = require('@replit/database');
       return new Database();
     }
     const file = process.env.DATA_FILE || path.join(__dirname, 'data.json');
     const read = () => {
       try { return JSON.parse(fs.readFileSync(file, 'utf8')); } catch { return {}; }
     };
     return {
       get: async (key) => read()[key] ?? null,
       set: async (key, value) =>
         fs.writeFileSync(file, JSON.stringify({ ...read(), [key]: value }, null, 2)),
     };
   }
   const db = makeStore();
  1. A different API port. Port 3000 on your machine is taken by a Rails app in Docker. Under your default Node 14, the frontend's /api calls went to that Rails app instead of this one.
  • In server.js: const port = process.env.API_PORT || 3000;
  • In vite.config.js: target: `http://127.0.0.1:${process.env.API_PORT || 3000}`

Then:

npm install
API_PORT=3001 npm run start
# open http://localhost:5000

With those changes, reads and writes worked and persisted to data.json on both Node 14.19.1 and Node 22.19.0. I only tested with curl, not by clicking through the page in a browser. Replit runs Node 20, so I'd put nodejs 22.19.0 in a .tool-versions file in the repo, and add data.json to .gitignore.

My test also sent a few GET/POST /api/dishes requests to your Docker Rails app; they returned routing errors and nothing else.

To bring over the real data, save the output of /api/dishes from the live Replit app and put it in data.json as {"dishes": [...]}.

Hosting elsewhere

Any other host needs two changes first:

  • Storage: something other than the Replit database, such as the JSON file above or a hosted key-value store.
  • Serving: npm run start runs the Vite dev server, which is also what Replit serves in production. Elsewhere, Express should serve the built dist/ folder and listen on the host's PORT. vite build works; I haven't written or tested the Express part.

| Option | Storage | Code change |
|---|---|---|
| Fly.io or Railway | JSON file on a persistent volume | Smallest: the fallback above plus Express serving dist/ |
| Render | Hosted Postgres or Redis, since its disk is not persistent by default | Small, plus swapping the store |
| Cloudflare Workers, Vercel or Netlify | Their key-value store (one key is all you need) | Rewrite server.js as two small functions; frontend deploys as static files |
| A server you already run | JSON file or SQLite | Same as Fly.io, behind your own reverse proxy |

I'd go with Fly.io or Railway with a volume, because the app keeps its current shape. Cloudflare Workers with KV is the better choice if you want it free and maintenance-free and don't mind the small rewrite. I haven't checked current pricing or free tiers for any of these.

how do i add a custom domain on fly.io?
Claude Code claude-fable-5-2 (xhigh) thought for 18s · 19s wall-clock time

Three steps, none of which need a code change or a redeploy. Substitute your real domain for dinner.example.com.

  1. Tell Fly about the domain, from the repo:
   fly certs add dinner.example.com

It prints the DNS records it wants you to create.

  1. Add the DNS record where your domain is managed.
  • For a subdomain like dinner.example.com: a CNAME from dinner to tgdinner.fly.dev.
  • For a bare domain like example.com: an A record to 66.241.125.80 and an AAAA record to 2a09:8280:1::216:a1ff:0, which are your app's current addresses.
  1. Check that the certificate was issued:
   fly certs check dinner.example.com

Once it reports the certificate as issued, https://dinner.example.com works. Fly gets the certificate from Let's Encrypt and renews it automatically.

  • The IPv4 address is a shared one, which is fine for a website; you don't need to buy a dedicated address.
  • If your DNS is on Cloudflare, set the record to "DNS only" rather than proxied, or the certificate check can fail.
  • tgdinner.fly.dev keeps working alongside the custom domain.
  • Cost: Fly's pricing page lists the first 10 single-hostname certificates as free.

I haven't run any of this; your app has no certificates yet. If you lose the DNS instructions, fly certs setup dinner.example.com shows them again.
